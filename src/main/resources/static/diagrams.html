UML и ER Диаграммы — Проект «Автопарк» (Вариант 4)

1. Диаграмма классов (UML Class Diagram)

Структура классов, перечислений, полей, методов и связей между ними.

classDiagram direction TB class VehicleCategory { <<enumeration>> MOTORCYCLE CAR TRUCK BUS } class VehicleStatus { <<enumeration>> AVAILABLE IN_USE NEEDS_MAINTENANCE } class Driver { -Long id -String fullName -Set~VehicleCategory~ categories -boolean busy +getId() Long +getFullName() String +isBusy() boolean +setBusy(boolean) void +getCategories() Set~VehicleCategory~ } class Vehicle { -Long id -String licensePlate -String model -VehicleCategory category -VehicleStatus status +getId() Long +getLicensePlate() String +getModel() String +getCategory() VehicleCategory +getStatus() VehicleStatus +setStatus(VehicleStatus) void } class Trip { -Long id -Driver driver -Vehicle vehicle -LocalDateTime startTime -LocalDateTime endTime +getDurationHours() long } class MaintenanceRecord { -Long id -Vehicle vehicle -LocalDateTime timestamp -String description } class FleetService { +startTrip(Long driverId, Long vehicleId, LocalDateTime start) Trip +finishTrip(Long tripId, LocalDateTime end) Trip +performMaintenance(Long vehicleId, String desc, LocalDateTime time) MaintenanceRecord +getDriverWorkHoursReport() Map~String, Long~ +getVehicleUsageReport() Map~String, Long~ } Driver "1" --> "*" VehicleCategory : открытые категории Vehicle "*" --> "1" VehicleCategory : требует категорию Vehicle "*" --> "1" VehicleStatus : имеет статус Trip "*" --> "1" Driver : выполняет водитель Trip "*" --> "1" Vehicle : используется авто MaintenanceRecord "*" --> "1" Vehicle : обслуживает авто FleetService ..> Trip : управляет FleetService ..> MaintenanceRecord : регистрирует ТО

3. Диаграмма состояний автомобиля (UML State Diagram)

Жизненный цикл статусов автомобиля от выезда в рейс до прохождения ТО.

stateDiagram-v2 [*] --> AVAILABLE : Регистрация авто в парке AVAILABLE --> IN_USE : startTrip() [Водитель свободен и подходит категория] IN_USE --> NEEDS_MAINTENANCE : finishTrip() [Возврат из рейса] NEEDS_MAINTENANCE --> AVAILABLE : performMaintenance() [Будни ПН-ПТ 08:00-17:00]

4. Диаграмма последовательности (UML Sequence Diagram)

Взаимодействие сервисного слоя и репозиториев БД при выполнении операций.

sequenceDiagram autonumber actor Client as Диспетчер (Клиент) participant Service as FleetService participant DriverRepo as DriverRepository participant VehicleRepo as VehicleRepository participant TripRepo as TripRepository participant MaintRepo as MaintenanceRepository Client->>Service: startTrip(driverId, vehicleId, startTime) Service->>DriverRepo: findById(driverId) Service->>VehicleRepo: findById(vehicleId) Service->>DriverRepo: save(driver [busy=true]) Service->>VehicleRepo: save(vehicle [status=IN_USE]) Service->>TripRepo: save(new Trip) Service-->>Client: Trip Client->>Service: finishTrip(tripId, endTime) Service->>TripRepo: findById(tripId) Service->>DriverRepo: save(driver [busy=false]) Service->>VehicleRepo: save(vehicle [status=NEEDS_MAINTENANCE]) Service->>TripRepo: save(trip) Service-->>Client: Trip Client->>Service: performMaintenance(vehicleId, desc, time) Service->>VehicleRepo: findById(vehicleId) Service->>VehicleRepo: save(vehicle [status=AVAILABLE]) Service->>MaintRepo: save(new MaintenanceRecord) Service-->>Client: MaintenanceRecord
